# Диагностика щелчков

В `config.h` включены `DEBUG_AUDIO_DIAGNOSTICS=1` и `DEBUG_STREAM_STATS`.
Новые счётчики не исправляют звук, а помогают определить источник дефекта.
Для сравнения нагрузки можно собрать вариант с `DEBUG_AUDIO_DIAGNOSTICS=0`.

## Проверка на плате

1. Перезагрузить плату и воспроизвести одиночную длинную ноту без лупа.
2. Отпустить ноту, дождаться завершения голосов и сохранить строки `[STREAM]`,
   `[AUDIO]`, `[AEVENT]` и `[GUI]`. Отчёт выводится раз в пять секунд только
   при отсутствии активных голосов; хвост реверберации ещё может звучать.
3. Повторить после перезагрузки с MIDI-файлом, на котором слышны щелчки.
   Желательно отметить время слышимого дефекта относительно запуска платы.

Счётчики и максимумы накопительные с момента загрузки. При непрерывной игре
отчёт откладывается до завершения голосов. Нужен полный отчёт, даже если
большинство полей равны нулю.

## Поля отчёта

| Поле | Значение |
| --- | --- |
| `starts`, `start_peak_ppm` | Число начал звучания и максимальная амплитуда первого выходного кадра голоса |
| `eof`, `eof_peak_ppm` | Завершения по концу файла и максимальная амплитуда последнего кадра перед завершением |
| `env_end` | Завершения по огибающей |
| `force_stop`, `stop_peak_ppm` | Немедленные остановки и максимальная амплитуда обрываемого голоса |
| `release`, `fast_release` | Запросы обычного и ускоренного затухания |
| `control_holds`, `hold_peak_ppm` | Короткие синхронизации с управляющим ядром, во время которых повторён последний кадр голоса вместо вставки нуля, и его максимальная амплитуда |
| `release_jumps`, `release_jump_peak_ppm` | Число первых кадров после обычного Note Off и максимальный перепад относительно предыдущего кадра |
| `swaps` | Число переходов между потоковыми PCM-буферами |
| `seam_errors` | Несовпадения кадра для интерполяции в конце предыдущего буфера с первым кадром следующего; ожидается ноль |
| `underruns` | Эпизоды отсутствия готового PCM-буфера |
| `read_errors` | Ошибки заполнения PCM-буфера |
| `clip_frames`, `mix_peak_ppm` | Число стереокадров за пределами ±1 перед ограничителем и максимальная амплитуда микса |
| `nonfinite` | Кадры с NaN/Inf; ожидается ноль |
| `jump_blocks`, `jump_peak_ppm` | Блоки с межкадровым скачком не меньше 0.05 и максимальный скачок после ограничения амплитуды |
| `compute_max_us`, `slow_blocks` | Максимальное время генерации/микширования блока без ожидания I2S и число превышений длительности блока |
| `i2s_errors` | Ошибки API записи I2S или неполные записи |
| `control_gaps`, `control_max_us` | Интервалы между проходами управляющей задачи больше 4000 мкс при активных голосах и их максимум |
| `dropped_events` | Не поместившиеся подробные события отдельно для audio/control; основные счётчики продолжают работать |

Амплитуды `ppm` даны в миллионных долях: 1000000 = 1.0. Для отдельных
голосов это сигнал до общего ослабления микшером; для микса — после громкости
и эффектов. Их нельзя напрямую сравнивать как одинаковую выходную громкость.
Ненулевые старты, остановки и скачки — кандидаты для проверки, а не доказательство
слышимого щелчка. Естественная атака инструмента тоже даёт скачок.
`slow_blocks` не доказывает аппаратный underrun: DMA имеет запас буферов.
`i2s_errors=0` также не гарантирует отсутствие всех сбоев на физическом выходе.

## Подробные события

`[AEVENT]` содержит ядро-источник, `t_ms`, тип, номер голоса, MIDI-ноту,
`pos` и `value`. Значение 255 для голоса/ноты означает отсутствие информации.
Позиция голоса — накопленное продвижение по исходным кадрам, а не смещение
в WAV при циклическом воспроизведении. Для паузы позиция не фиксируется.
`t_ms` получен из `micros()` и оборачивается примерно через 71.6 минуты.

`value` обычно содержит амплитуду ppm; у `seam_error` — разницу в целых
единицах 16-битного PCM, у `control_gap_us` — микросекунды, у `i2s_error` —
код возврата API (его `pos` содержит число записанных байтов).
Остановки/удержания/EOF записываются подробно при амплитуде от 0.01;
счётчики учитывают и более тихие события.

Каждое ядро имеет очередь на 16 событий без динамической памяти и печати
из аудиотракта. При переполнении сохраняются первые события, новые теряются.
Один отчёт извлекает до восьми событий из каждой очереди, поэтому после
остановки полезно дождаться нескольких отчётов. Диагностика добавляет нагрузку;
её влияние на реальной плате оценивается по времени обработки и сравнению
со сборкой без неё.
